# SQL 技巧：筛选某字段累计总和 = 0 的客户标识

> **日期**：2026-08-12
> **分类**：工具技巧
> **标签**：SQL、GROUP BY、HAVING、聚合过滤、累计求和

---

## 一、场景

表中每个客户每天产生一条记录，其中字段 `a` 为该客户当天的数值（正负均可）。现在需要**从客户的维度聚合**，找出所有字段 `a` 的**累计总和 = 0** 的客户标识。

即：将该客户全部历史记录的 `a` 求和，结果恰好为 0。

## 二、核心 SQL

```sql
SELECT 客户标识
FROM 你的表名
GROUP BY 客户标识
HAVING SUM(a) = 0;
```

**关键语法**：
- `GROUP BY 客户标识`：按客户维度聚合，把一个客户的所有行并成一组
- `HAVING SUM(a) = 0`：**过滤分组**。`HAVING` 是作用于聚合结果的条件，与 `WHERE`（作用于单行记录）不同
- `SUM(a)`：将该客户全部历史记录的 `a` 累加

## 三、易混淆的延伸情况

### 3.1 只想要「某一天」a 求和为 0 的客户

若需求是"只看某一天的累计"，应先在聚合前用 `WHERE` 限定日期范围：

```sql
SELECT 客户标识
FROM 你的表名
WHERE 日期 = '2026-08-12'
GROUP BY 客户标识
HAVING SUM(a) = 0;
```

### 3.2 某个截止日期之前的累计为 0

```sql
SELECT 客户标识
FROM 你的表名
WHERE 日期 <= '2026-08-12'
GROUP BY 客户标识
HAVING SUM(a) = 0;
```

## 四、注意事项

1. **`HAVING` 与 `WHERE` 的分工**：`WHERE` 在聚合前过滤原始行；`HAVING` 在聚合后过滤分组结果。想在分组内过滤行用 `WHERE`，想过滤分组本身用 `HAVING`。
2. **`a` 为 NULL 时**：`SUM` 会自动忽略 NULL。若客户该天记录本身就是 NULL/缺失，求和结果不受影响，但要注意该客户是否真的存在于分组结果中（有行的客户才会被 `GROUP BY` 归组）。
3. **判断"确实有记录"**：如果需要排除"某个客户其实一条记录都没有、只是恰好被算成 0"的边界情况，可加 `HAVING COUNT(客户标识) > 0`，ORM 场景下一般无需处理。
4. **字段名/表名**：实际使用时替换为真实表名与字段名，如 `customer_id`、`table_name`。

## 五、经验总结

1. **"累计 ××× = 某值"的客户筛选** = `GROUP BY 客户标识` + `HAVING SUM(字段) = 条件`，是标准套路。
2. **先问清楚"累计"的范围**：全历史 / 某天 / 某截止日前，直接改变 `HAVING` 前是否需要 `WHERE` 限定时间。
3. **聚合条件一律放 `HAVING`**，不要写成 `WHERE SUM(...) = 0`，那会报错（`WHERE` 不允许聚合函数）。
