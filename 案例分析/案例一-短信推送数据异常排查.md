# 案例一：短信推送数据异常排查 — 点击数大于推送成功数

> **日期**：2026-07-25
> **分类**：案例分析
> **标签**：数据异常、埋点、短信推送、跨平台数据核对

---

## 一、背景

在执行短信推送任务时，通过短信推送平台向用户批量发送包含引流埋点链接的短信。任务结束后进行数据复盘时，发现关键指标之间存在逻辑矛盾。

## 二、问题描述

| 指标 | 含义 | 数值（脱敏） |
|------|------|-------------|
| A | 短信推送平台显示的推送总量 | A（较大） |
| B | 短信推送平台统计的实际推送成功数 | B（远小于A，成功率极低） |
| C | 埋点链接统计到的点击用户数 | C |

**核心矛盾**：C > B

按照正常逻辑链路：

```
推送总量 A ≥ 推送成功 B ≥ 收到短信用户数 ≥ 点击埋点链接用户数 C
```

点击用户数 C 不应大于推送成功数 B。出现 C > B，说明至少有一个平台的数据统计存在问题。

## 三、排查思路

### 3.1 可能的原因假设

| 编号 | 假设 | 方向 | 说明 |
|------|------|------|------|
| H1 | 短信推送平台成功数 B 统计偏低 | 推送平台问题 | 实际推送成功的数量大于平台统计的 B，导致 B 被低估 |
| H2 | 埋点点击数 C 统计偏高 | 埋点/数据平台问题 | 埋点逻辑存在重复计数、爬虫点击、或统计口径不一致 |
| H3 | 两个平台统计口径不一致 | 口径问题 | 例如推送平台按"送达运营商"统计，埋点按"去重点击"或"不去重点击"统计 |
| H4 | 存在非本次推送的流量混入 | 数据污染 | 埋点链接被其他渠道复用，或链接被转发/分享导致额外点击 |

### 3.2 排查方向

**优先排查短信推送平台侧**（当前进行中）：
- 核对推送成功数的统计口径（是"提交成功"还是"送达成功"）
- 确认是否有状态回调延迟导致成功数未及时更新
- 检查失败原因分布，确认 B 偏低是否合理

**随后排查埋点侧**：
- 确认点击数 C 的统计口径（去重维度：按用户 / 按设备 / 按点击事件）
- 检查是否存在爬虫/机器人点击
- 排查埋点链接是否被其他渠道复用

## 四、当前进展

- 已将问题反馈给短信推送平台，要求排查 B 的统计准确性
- 待平台反馈后，根据结果决定是否需要同步排查埋点侧

## 五、经验总结

1. **数据交叉验证意识**：多个数据源之间进行逻辑校验是发现数据异常的有效手段。本案例中，正是通过对比推送成功数与埋点点击数，才发现矛盾。
2. **指标逻辑链路思维**：建立「推送量 → 成功量 → 触达量 → 点击量 → 转化量」的漏斗逻辑链，任一环节出现逆序都意味着数据异常。
3. **先定位再归因**：发现异常后，先让相关平台自查，缩小问题范围，避免盲目排查。
4. **口径一致性是前提**：跨平台数据对比前，必须确认各平台统计口径是否一致，否则对比无意义。
5. **脱敏记录**：数据案例沉淀时，敏感数值用变量替代，保留分析逻辑即可复用。
